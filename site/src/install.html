Install

Install ACP in a project

ACP arrives with formal-project-bootstrap. You install the bootstrap into a project, connect your machine to a gateway, and the repository’s owner puts it under a policy once.

Python 3.11+ and GitThe client and bootstrap use the standard library only. Nothing to pip install.
A gateway tokenFrom whoever runs your ACP gateway. It lives in the macOS Keychain, or ACP_GATEWAY_TOKEN in CI and on Linux.
A GitHub repositoryACP reads it through a read-only GitHub App installed on the repository’s owner.
A registered policyUntil the gateway holds a policy naming the repository, protected actions are refused.

Today one gateway and one GitHub App serve their owner’s repositories. Running your own gateway is the beta milestone.

Set up

Five steps, once per project

  1. Get the bootstrapanywhere on your machine

    Clone the public repository at the latest signed release. You’ll run its installer against your project.

    git clone https://github.com/zachshallbetter/formal-project-bootstrap.git
cd formal-project-bootstrap
git checkout v0.7.3

  2. Install it into your projectfrom the bootstrap folder

    Pick the case that fits. All three leave only AGENTS.md at the project root; everything else goes under .agents/.

    A new project

    python3 .agents/bootstrap/scripts/init-project.py \
  --name "My Project" --id my-project --mode new --output ../my-project

    An existing project

    Inspect first; the inventory changes nothing. --mode existing never overwrites your files and stages any conflict for you to reconcile.

    python3 .agents/bootstrap/scripts/reconcile-project.py --project ../my-project --pretty
python3 .agents/bootstrap/scripts/init-project.py \
  --name "My Project" --id my-project --mode existing --output ../my-project

    A project on an older bootstrap

    Run this release’s upgrader from inside the project. It moves older layouts into .agents/, verifies the release signature, and commits exactly the upgrade.

    cd ../my-project
python3 ../formal-project-bootstrap/.agents/bootstrap/bootstrap upgrade --commit

  3. Connect this machinein the project, once per machine

    Tell the client which gateway to use, store the token, and let it fill in the project’s settings.

    .agents/acp/acp endpoints configure --set-name production \
  --endpoint vercel https://acp-gateway.vercel.app ACP_GATEWAY_TOKEN
.agents/acp/acp login
.agents/acp/acp init
    • login asks for the token with a hidden prompt and keeps it in the Keychain. It never appears in a file or on screen.
    • init reads the repository from origin, finds the project board, and declares automatic deploys when it sees vercel.json, .vercel/ or netlify.toml.
    • It’s safe to run again, and it makes sure .gitignore keeps .agents/ tracked.

  4. Put the repository under a policyrepository owner, once

    Governing a repository is the owner’s decision, made on the gateway with the owner’s own signing key. Install the ACP GitHub App on the account that owns the repository, then register it from the acp-gateway checkout.

    python3 scripts/policy-admin.py register OWNER/NAME          # dry run: shows the policy
python3 scripts/policy-admin.py register OWNER/NAME --apply

    The gateway loads a new policy on its next production deployment. Activating one without a redeploy is tracked in acp-gateway#47.

  5. Check everythingin the project

    One line per check, each with its fix: Python, layout, profile, compiled context, endpoints, token, client version, policy, the GitHub App, pinned files and the board.

    .agents/acp/acp status
# ACP is ready.
Every day

Use, upgrade, remove

  1. Push through ACP

    Runs your pre-push hook first, then asks for one exact approval per step: the temporary branch, the protected ref, and the deploy when main deploys automatically.

    .agents/acp/acp push --to main --dry-run   # show each approval it would ask for
.agents/acp/acp push --to main

    Decisions are logged on this machine in a git-ignored file. Copy the ones you want into the project’s evidence ledger with your next commit:

    .agents/acp/acp record          # list this machine's decisions
.agents/acp/acp record --all

  2. Upgrade

    acp status tells you when a newer release exists. The upgrade fetches the signed tag, checks every file against the release manifest, keeps your own files, and commits only the upgrade.

    .agents/bootstrap/bootstrap upgrade            # dry run
.agents/bootstrap/bootstrap upgrade --commit
.agents/acp/acp push

    If someone edited the client by hand, .agents/bootstrap/bootstrap repair restores the released files and keeps a copy of the edits.

  3. Remove

    Both are dry runs unless you add --apply. Your intent, profile and records stay, and everything removed is backed up.

    .agents/acp/acp uninstall --apply                # just ACP
.agents/bootstrap/bootstrap uninstall --apply    # the whole bootstrap

    The gateway keeps enforcing its policy until the owner runs policy-admin.py unregister OWNER/NAME. acp uninstall reminds you.

Where it lives

Everything stays under .agents/

Machinery is replaced on upgrade. Your files are never overwritten.

AGENTS.md                  the one bootstrap file at the root
.agents/
  acp/                     the ACP client: acp, lib/, schemas/, README.md
  bootstrap/               bootstrap machinery: bootstrap, scripts/, docs/, templates/
  project/                 yours: intent, profile.json, bindings, contracts/, rules/
  records/                 yours: evidence, negative results, deviations
    local/                 this machine's decision log (git-ignored)
  skills/                  agent skills the bootstrap ships
  context-lock.json        compiled context, checked on every commit
  board.env                which board and repository this project uses
