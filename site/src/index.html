Agent Control Plane

nounACP
An authorization service for AI agents. Before an agent does something it can’t take back, such as pushing to a protected branch, deploying or migrating a database, it asks ACP. ACP checks the facts for itself and answers for that one action, at that one commit, for about a minute. Anything it can’t verify is refused.

The idea underneath

ACP stands at the last undo

In The Last Undo from Judgment Machines, the last undo is the final point where an action can still be reversed by you alone, cheaply and completely. After it, a fix is remediation. ACP makes its decision at exactly that point.

Still reversible
  • Commit on a branch
  • Run the project’s own checks
  • Publish to a temporary acp/<sha> branch

The field card (PDF) · Read the introduction

On the field cardHow ACP represents it
What are you about to make consequential?One protected action: an action name, a ref, and the old and new commit. Nothing broader is ever approved.
Can it still be undone unilaterally, cheaply, completely?ACP is asked immediately before the push. Branch work and the temporary branch stay reversible; moving main and deploying don’t.
Required propertiesWhat the signed policy requires, checked against ACP’s own reads of GitHub and the control files the client reports.
Satisfied · Violated · GrayVerified evidence · a mismatch · state that’s only self-reported or can’t be verified.
Unresolved ≠ satisfiedSelf-reported state never authorizes, more reporting never promotes it, and no answer from ACP counts as a refusal.
Who has authority if a property is gray?For a fact, nobody: ACP refuses until it can verify. For a judgment, the owner, through an exact, expiring, signed grant. Never an agent.
Pass · Fail · EscalateALLOW (A0) · DENY or QUARANTINE (A1, A4) · held until verified (A3), or the owner’s one-time recovery authorization (A6).
Record evidence and authority before the actEvery decision gets a request id in the hash-chained audit log before anything is pushed. acp record copies it into the project’s evidence ledger.

Three pieces carry the name

Two work together today. The third is an earlier, separate tool with its own decisions, and no document yet joins it to the other two.

Decides

acp-gateway

The policy decision service. It holds signed policies, reads GitHub for itself as evidence, returns one of eight decisions, and keeps containment and audit state on the server.

The ACP client

Ships in every bootstrapped project at .agents/acp/. One command sets it up, checks status and pushes with one exact approval per step. It fails closed when no valid decision comes back.
